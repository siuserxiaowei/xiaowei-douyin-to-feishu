# 抖音文案与逐字稿

把抖音页面发布的文案和视频里说出的口播分开交付。口播必须来自实际取稿或语音识别结果，不能用标题、简介、评论、摘要或模型续写冒充。

## 先确定本次交付

- 用户说“试一下能否提取”“只要文案/逐字稿”时，先做取稿测试：返回视频来源、发布文案、口播逐字稿全文、取稿方式和完整性状态；不创建飞书文档。
- 用户明确说“存飞书”时，完成取稿后创建或更新飞书文档，读回新增逐字稿全文核对，再交真实文档链接。取得本地文件不是完成条件。
- 用户只要发布文案、不需要口播时，不启动语音识别。用户说“抖音文案”但未限定种类时，分别给出发布文案和口播逐字稿，缺一项就如实标注。
- 单条视频先跑通；主页或批量任务按视频 ID 逐条去重，保留各条状态。主页默认最近发布的 5 条公开视频，置顶不等于最新。

## 取稿：先用上游原理，再用当前环境能跑通的路径

上游 social-media-data-tools 的快速路径依赖豆包工作内置的 web.fetch；这个工具不是上游仓库中的脚本，也不随本技能安装。先检查当前豆包工作会话的实际工具列表。普通网页抓取、浏览器页面文字或同名外部工具不一定含口播，不能代替它。

1. 从分享文案提取链接，用浏览器展开短链，记录规范视频 URL 和视频 ID。主页链接先通过当前可用浏览器取视频 URL，必要时由用户在浏览器里完成登录。
2. 如果当前会话确实提供能返回抖音逐字稿的 web.fetch，按 `references/extraction.md` 中的调用与分页规则读取。首请求使用视频 URL 和 pagination={offset:0,limit:4000}；后续以返回的 end_offset 作为下一页 offset，直到 end_offset 到达 total_length。保存各页原始结果，检查无遗漏、无重复拼接，再从返回内容中辨认标题/发布文案与口播正文。
3. 若没有该能力、返回普通网页、调用失败或分页不完整，直接走已验证的音频路径：用浏览器会话配合 yt-dlp 取得媒体和可用的页面 description，再用当前已提供的 mediakit Cloud ASR 或其他真实可用的转写服务取得全部字幕。`scripts/audio_fallback.py download` 可提取 WAV；把它生成的 `result.json` 作为视频元数据传给 `scripts/assemble_asr.py`，将 Cloud ASR 分段 JSON 组装为 `transcript.txt` / `run.json`。组装时必须有独立的视频时长；不能用 ASR JSON 的 duration 代替。运行参数以当前工具和脚本 `--help` 为准。
4. doubao-video-extract 只有在其当前说明确认支持抖音时才可尝试；先前环境明确拒绝 douyin.com，应跳过。旧移动分享页 _ROUTER_DATA 解析已被平台变化破坏，不作为主路径。本地 SenseVoice 仅在依赖与模型已备好时可用，不自动安装大型模型。

详细的工具判别、分页和音频回退见 `references/extraction.md`。取得一次可用音频或 ASR 任务 ID 后要复用结果；失败时记录具体阶段，不反复下载或提交相同任务。

## 核对与交付

- 内置取稿路径：核对 start_offset / end_offset / total_length 连续且终点已到达；工具结果被截断、offset 不前进或正文只是摘要时，不声称全文。
- ASR 路径：确认任务完成、分段顺序与时间范围覆盖视频首尾。明显缺段或时间轴可疑间隔先标为“部分/待核实”，回听对应音频后区分漏识与自然静音；不要把自动识别说成“已逐字校对”。
- 过短或没有结束标点只是疑点，不能单凭这两点判失败；“获取”等普通词也可能是原话。确实没有口播要有音频或可信工具证据，空结果不等于无口播。
- 保留未改写的原始 `transcript.txt` 与运行记录。发布文案单独保存为 `description`；它不是口播，不能混进逐字稿。速览或 AI 提炼与原文分区，绝不补写未听到的话。

取稿测试时直接给用户完整文字，长稿按顺序分段展示，不用摘要替代全文。先写明“内置取稿全文”“ASR 全文已取回、未逐字校对”“部分内容”或“未取得逐字稿”，再给发布文案与口播。未取得的字段写“未获取”及原因，不造假。

## 需要存飞书时

按 `references/document-format.md` 整理正文，按 `references/feishu-docs.md` 写入和读回。已存在 `run.json` 和 `transcript.txt` 时直接续跑飞书阶段，不重新取稿：单条新建或已有同视频文档可用 `scripts/publish_feishu.py <run.json>`；向其他已有文档追加时，先读原文，按视频 ID 去重后再追加并核对。不要把脚本的“已有文档核对”误当成自动追加。

用户要求存飞书已经授权该次创建或追加；不另行扩大共享权限、不向其他人发送消息、不覆盖原有内容。创建响应不确定时先定位原文档，不能盲目再建一篇。只有真实文档 URL 且新增逐字稿全文读回一致，才能报告“已存飞书”。认证或权限失败时明确交付未完成状态和恢复线索。
