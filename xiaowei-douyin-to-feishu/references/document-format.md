# 飞书正文格式

单条文档标题：`抖音逐字稿｜视频标题`。批量标题：`抖音逐字稿｜作者或主题｜采集日期`。没有可靠原标题就用视频 ID，不替作者编标题。

单条视频正文按顺序包含：

1. 来源链接、视频 ID、作者、发布时间、采集时间。未知信息写“未获取”；无关的互动数据不占篇幅。
2. 全文状态和实际获取方式。明确“全文取回”与“逐字准确”不同；有缺段时在正文之前说明。
3. 内容速览（AI 提炼），默认 1–3 个要点。用户只要原文时省略。
4. 逐字稿。保留全部文字、口语、重复句和原始时间戳；可按停顿或话题换段，不能删改或补写。部分内容时章节名改成“已取得的逐字稿（不完整）”。
5. 必要的缺失说明。有问题才写，没有则省略。

批量文档在前面放一段数量与失败情况说明；每条视频作为二级标题，内部使用三级标题。不要把长逐字稿装进表格、代码块或折叠摘要。

速览的文风：短句、具体动词、少形容词；用原文中的具体问题和论点说清楚。不写“深度赋能”“颠覆认知”等自行加上的判断。作者口播中的词不受此编辑规则影响。

## 确定性生成 Markdown

`scripts/build_document.py` 接收一份元数据 JSON，将指定的逐字稿文件按原字序写入 Markdown。相对文件路径按元数据文件所在目录解析。只把文本中的格式字符转义，不改写内容；输出一个正文文件和一个用于核验的清单。两个输出路径必须尚不存在。

```bash
python3 scripts/build_document.py ./runs/batch.json --output ./runs/document.md
```

元数据示例（所有示例值应替换为本次真实数据）：

```json
{
  "title": "抖音逐字稿｜本次主题",
  "collected_at": "2026-09-24T15:00:00+08:00",
  "videos": [
    {
      "video_id": "1234567890123456789",
      "source_url": "https://www.douyin.com/video/1234567890123456789",
      "title": "视频原标题",
      "author": null,
      "published_at": null,
      "method": "豆包工作内置逐字稿",
      "status": "complete",
      "transcript_file": "video-1/transcript.txt",
      "summary": ["仅写原文支持的概括"],
      "note": ""
    }
  ]
}
```

`status` 枚举：`complete`、`partial`、`failed`、`no_speech`，对应入口文件中的四种状态。`complete` 和 `partial` 需要非空逐字稿；`partial` / `failed` / `no_speech` 需要 `note` 说明缺段、错误或无口播证据。`failed` / `no_speech` 不接收稿件或 AI 摘要，避免误当成功。只要原文时使用空的 `summary` 数组。

生成器拒绝重复视频 ID、来源与 ID 不一致、空的成功稿件以及超出 3 条的摘要；完成状态由真实工具证据决定，生成器不判断 ASR 正确率。核验清单记录每条原始稿件 SHA-256 和字数，不是飞书已保存的证明。

不要把本地路径、SHA-256、任务 ID、安装说明等执行细节展示在普通读者的飞书正文中；保存在运行记录用于恢复。必要的来源和全文缺失说明应保留。
