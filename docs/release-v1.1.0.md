# v1.1.0 · 先验证抖音取稿，再按需存飞书

按 [social-media-data-tools](https://github.com/jinchenma94/social-media-data-tools) 的实际工作原理重写取稿流程：当前豆包工作会话若提供能返回抖音口播的内置 `web.fetch`，从 `offset=0, limit=4000` 开始，按返回的 `end_offset` 继续读取，直到覆盖 `total_length`。该内置工具不是上游仓库代码的一部分，也不会因安装本 Skill 自动出现。

- 增加“只测试提取”模式：分别交付页面发布文案和完整口播，说明取稿路径、分页或字幕覆盖状态；不创建飞书文档。
- 没有内置取稿能力时，继续使用已经跑通的浏览器会话 + `yt-dlp` + mediakit Cloud ASR。新增 `assemble_asr.py`，从真实 ASR 分段 JSON 生成逐字稿和可续跑运行记录；缺视频时长或明显缺段不会冒充全文。
- `yt-dlp` 元数据中的 `description` 作为页面发布文案独立保存；要求存飞书时，发布文案与口播分节写入并分别读回核对。
- 保留 v1.0.1 的飞书续跑和去重恢复规则，更新使用说明与验证边界。

本版用同一条真实视频重新在线提取音频及页面配文，再把此前保存的 142 段 ASR 结果重组为 1241 字，与之前的原稿逐字一致。46 项离线测试通过。内置 `web.fetch` 路径因当时环境未提供该工具，仍待具备该能力的会话实测；自动语音识别文字未经过人工逐字校对。

下载 `xiaowei-douyin-to-feishu-v1.1.0.zip`，导入整个技能文件夹。建议先照 [使用说明](usage.md) 中的“只测试取稿”提示词运行一条公开视频，再决定是否保存飞书。
